# 双休聘 · 项目分析（设计说明）

> 项目名：**双休聘**（聚焦"双休"的招聘 + 企业点评社区）
> 许可证：**GNU AGPL-3.0**（最严格，全仓库统一，任何分发/网络服务都必须开源）
> 文档版本：v1.0（2026-09-13）

---

## 1. 需求解读与边界

### 1.1 产品定位
- 核心差异化：职位卡片与公司点评都以「双休 / 单休 / 不定」为一等公民（绿=双休、红=单休、红黑=不定）。
- 形态：**全面手机端 H5 应用**，前端为 React SPA，最终以 **WebView 壳** 方式上架应用商店。**不做 React Native / Flutter 等编译方案**。
- 平台**不支持任何私信**：普通用户之间、普通用户与企业招聘用户之间均无私信。消息中心只有「系统消息」与「广场互动消息」。

### 1.2 角色与权限矩阵

| 能力 | 系统管理员 | 运营管理员 | 企业招聘用户 | 普通用户 |
| --- | --- | --- | --- | --- |
| 登录方式 | 邮箱+密码（默认管理员首登强制改密） | 邮箱+密码 | 邮箱（密码 / 找回） | 邮箱（密码 / 找回） |
| 用户账号增删改查（建号/封禁/重置密码/删号/授角色） | ✅ | ❌ | ❌ | ❌ |
| 编辑/删除用户**发表内容**（帖子/评论/评价/公司资料） | ❌ **明确禁止** | ✅（社区运营、审核） | ❌ | ❌ |
| 企业认证：人工按用户 ID 认证、审核认证申请 | ❌ | ✅ | ❌ | ❌ |
| 发布职位 | ❌ | ❌ | ✅ | ❌ |
| 公司/点评主体**编辑与管理** | ❌ | ✅ | ❌ | 仅能创建（名称不存在时） |
| 发帖/评论/点赞/转发/关注/点评 | ❌ | ❌ | ✅ | ✅ |

- 系统管理员**只能管理"用户本身"（账号维度）**，接口层面就不提供其编辑任何 UGC 的入口。
- 运营管理员职责：社区内容运营与审核（隐藏/恢复/删除 UGC、维护公司资料）、企业认证审核（收到申请后**人工在后台输入用户 ID** 认证，**绝不自动升级**）。

### 1.3 关键规则
- **注册邮箱白名单**：只允许国内知名邮箱域（163/126/qq/foxmail/sina/sohu/aliyun/139 等），列表存 MySQL，可由后台维护。
- **邮箱验证码**：6 位数字；**同一邮箱 60 秒内只能发一次**（Redis SETNX+TTL）；验证码 10 分钟有效；**每个验证码最多输错 5 次**，超次作废；注册/找回密码两个用途互不通用。
- **企业认证流程**：普通用户提交申请 → 系统发送邮件到「我方运营邮箱」（config 配置）→ 运营管理员在后台人工审核；运营也可直接输入用户 ID 一步认证。通过后用户角色升级为企业招聘用户，并邮件通知用户。
- **公司主体 ⇄ 点评主体一体**：按**企业名称全局唯一**，谁先创建都归大家共用（1:1 同一条记录）。创建入口对所有登录用户开放（发职位时企业用户可顺手建公司；点评页任何用户可先建主体）。
  - ⚠️ 需求原文「一旦创建则只能由运营管理员创建/管理」存在歧义，本实现采取的口径：**创建开放（名称不存在即可建），创建后的编辑/维护仅限运营管理员**。此口径在 README 中明示；如需改为"仅运营可创建"，只需在路由层收紧一个中间件。
- **职位内容占位**：职位详情页本期只做占位（字段齐全、页面先展示基础信息 + 占位文案）。
- **排序**：首页/搜索结果仅做「最新」排序，其余排序预留参数不做；点评主体列表支持 评分最高/最低、评分人数最多/最少；评论回复默认按点赞排序，可切最新。
- **许可合规**：面向应用商店上架，需拟定《用户协议》《隐私政策》（见 `docs/`），App 内"设置"页可查看；注册页需勾选同意。

## 3. 总体架构

```
┌─────────── WebView 壳（上架用） ───────────┐
│  React SPA (Vite build 产物, /web/dist)     │
│  路由守卫 → 未登录访问 消息/我 → /login      │
└───────────────┬───────────────┬────────────┘
        HTTPS (JSON /api)   WebSocket /api/ws
                │               │
        ┌───────▼───────────────▼───────┐
        │        Gin (server/)          │
        │  middleware: 恢复/日志/CORS/   │
        │  会话鉴权/RBAC/强制改密守卫     │
        │  handler → service → gorm     │
        └───┬──────────┬──────────┬─────┘
            │          │          │
        MySQL 8     Redis 7     SMTP
     (业务数据)   (会话/验证码/   (验证码、认证
                   在线状态/限频)   通知邮件)
```

- 前端产物可由 Gin 静态托管（生产单进程），开发期 Vite dev server 代理 `/api`。
- WebSocket 连接即在线：客户端每 30s 发 `{"type":"ping"}`，服务端刷新 Redis `online:<uid>`（TTL 120s）；断开删除。在线状态可扩展好友在线/招聘方在线等。
- 新互动（点赞/评论/回复/关注/转发/系统消息）产生时：写 `notifications` + 通过 Hub 实时推送该用户所有连接 `{"type":"notification"}` 与最新未读数。

## 4. 数据模型（MySQL, utf8mb4）

| 表 | 说明 | 关键字段 |
| --- | --- | --- |
| users | 全角色统一账号 | email(唯一,小写)、password_hash、nickname、avatar、bio、contact_email、role(1普通/2企业/3运营/4系统)、status(1正常/2禁用)、must_change_pwd、软删 |
| email_domains | 注册邮箱域名白名单 | domain(唯一)、enabled |
| companies | **公司主体=点评主体（1:1）** | name(全局唯一)、logo、industry、size、funding、rest_type(1双休/2单休/3不定)、rating_sum、rating_count、review_count、created_by |
| jobs | 职位 | company_id、publisher_id、title、salary_min/max(k)、education、experience、city/district/street(三段式)、description(占位)、status(在招/下架) |
| posts | 帖子（=作品） | user_id、content、repost_of_id(转发引用)、like/comment/repost_count、status(正常/隐藏)、软删 |
| comments | 帖子评论+回复（两级） | post_id、user_id、parent_id(空=评论)、reply_to_user_id、content、like_count、reply_count |
| reviews | 企业评价 | company_id、user_id、overall(1-5)、dims(JSON:氛围/福利/强度/发展)、content、like_count |
| likes | 多态点赞 | user_id+target_type(1帖/2评论/3评价)+target_id 唯一 |
| follows | 关注 | follower_id+followee_id 唯一 |
| notifications | 消息中心 | user_id、type(1系统/2赞/3评论回复/4关注/5转发)、sender_id、post_id/company_id、content、is_read |
| cert_requests | 企业认证申请 | user_id、company_name、note、status(待审/通过/驳回)、reviewed_by |
| verification_codes | 验证码审计（快速路径在 Redis） | email、purpose、code、expires_at、used |

计数（点赞数/评论数/转发数/评分等）均**冗余计数列** + 事务内增减，列表零 JOIN 聚合。

## 5. API 规划（统一前缀 /api，信封 {code,msg,data}，会话 Cookie 鉴权）

- 认证：`POST /auth/code`(发验证码) `/auth/register` `/auth/login` `/auth/logout` `/auth/password`(改密/强制改密) `/auth/reset`(验证码重置) `GET /auth/me`
- 用户：`PUT /me` `GET /users/:id`(主页+作品) `POST /upload`(图片) `GET /dicts`
- 关注：`POST /follows/:uid/toggle` `GET /follows/:uid`
- 职位：`GET /jobs`(kw+最新+城市+六维筛选) `GET /jobs/:id` `POST /jobs` `GET /jobs/my` `PUT /jobs/:id` `POST /jobs/:id/close|open`
- 公司点评：`GET /companies`(排序:评分高低/人数多少) `POST /companies` `GET /companies/:id` `POST /companies/:id/reviews` `GET /companies/:id/reviews`
- 社区：`GET /posts?tab=latest|follow` `POST /posts`(含转发) `GET /posts/:id` `DELETE /posts/:id` `GET /posts/:id/comments` `POST /posts/:id/comments` `GET /comments/:id/replies` `POST /likes`(toggle)
- 搜索：`GET /search/jobs|posts|companies|users`
- 消息：`GET /messages?type=system|interact` `POST /messages/read` `GET /messages/unread`
- 认证申请：`POST /cert-requests` `GET /cert-requests/my`
- WS：`GET /ws`（ping/pong 心跳、notification/unread 推送）
- 系统管理控制台：`/sys/users`(CRUD/重置密码/封禁/授权)、`/sys/email-domains`(白名单维护)、`/sys/notify`(系统消息) —— **独立前缀 + 仅内网中间件**，与运营功能完全隔离
- 运营管理后台：`/admin/certs`(列表/审核)、`/admin/certify`(按用户ID直接认证)、`/admin/posts|comments|reviews`(隐藏/恢复/删除)、`/admin/companies`(维护资料)

## 6. 非功能设计

- **会话安全**：Cookie HttpOnly + SameSite=Lax，SID 为 32 字节随机数，Redis TTL 7 天滑动；禁用用户即时踢下线（登录后回查状态）。
- **验证码防刷**：60s/次（Redis SETNX）、10 分钟有效、5 次错误作废、每邮箱每日上限 20 条。
- **性能**：列表分页懒加载（InfiniteScroll）、卡片 `content-visibility:auto` 懒渲染、图片 lazy、计数列免聚合、会话/验证码/在线状态全在 Redis。
- **安全**：bcrypt、上传类型/大小白名单、SQL 全走 gorm 参数化、XSS 由 React 转义 + 内容纯文本、管理员与用户能力接口层隔离。
- **合规**：AGPL-3.0 全文在根目录 LICENSE；《用户协议》《隐私政策》随仓库与 App 内页面提供。
